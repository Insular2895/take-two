# Phase M governed-context propagation — pre-patch audit

Date: 2026-08-24

Branch: `codex/v10-quantitative-validation-and-robust-decision-engine`

## Classification

`CONFIRMED` — the requested integration gap exists.

The repository is `PARTIAL` with respect to the target architecture: the lower-level budget and
candidate contracts already support the governed inputs, but the generic decision entry point does
not propagate them as one canonical prospective context.

## Verified current state

| Area | Classification | Finding |
|---|---|---|
| `enumerate_candidates` | `ALREADY_FIXED` | Accepts `FlexibleBudgetPolicyV2`, `FXRate`, `FXExecutionCost`, `BrokerCapitalContext`, and `MixedExpiryLifecycleConfiguration`, then passes them to the factory. |
| `build_candidate` | `PARTIAL` | Accepts all five inputs and evaluates them, but can silently construct a default lifecycle and can reconstruct FX evidence from `TradeRequest`. |
| `analyze_trade` | `CONFIRMED` gap | Accepts only a loose budget policy, reconstructs one FX rate from `TradeRequest`, and does not propagate FX execution cost, broker capital, or governed lifecycle. |
| `build_trade_economics_ticket` | `PARTIAL` | Accepts the loose policy/runtime inputs, but obtains lifecycle from `MarketDataBundle` and may reconstruct broker or FX-cost evidence. It has no canonical Phase M context identity/hash. |
| prospective YAML | `ALREADY_FIXED` values | The canonical file contains the approved V2 budget and one-day mixed-expiry lifecycle values, but the Pydantic lifecycle field currently has a silent default. |
| Cloud dossier | `PARTIAL` | Carries ticket/config/market hashes but not a Phase M context ID/hash. |

## Initial propagation graph

```text
loose budget policy -------------------------------> analyze_trade
TradeRequest.fx_rate_to_usd -- reconstructed FX ---+
                                                     |
                                                     v
                                              enumerate_candidates
                                                     |
       optional fx_cost / broker / lifecycle --------+  (not supplied here)
                                                     v
                                               build_candidate

MarketDataBundle.trade_economics ------------------> TradeEconomicsTicket lifecycle
loose ticket arguments / reconstructed evidence ---> TradeEconomicsTicket budget diagnostics
```

There is no single object tying the static policy, runtime evidence, provenance, and stable hash
together. Candidate and ticket lifecycle configuration can therefore originate from different
objects.
